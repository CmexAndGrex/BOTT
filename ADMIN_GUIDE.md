1. **Арсенал** (`/armory`) — каталог выкладок по специальностям: командир заводит комплект из экспорта ACE Arsenal, боец копирует строку в игру одной кнопкой. Подробности — раздел 6.

## Что нового в v1.7 (кратко)

4. Встроенный **планировщик** (тик каждые 20 сек) выполняет пинги на операцию, недельную проверку онлайна и фоновую синхронизацию состава.

## 1. Редакция ШДС и управление составом

### 1.1. Как работает синхронизация состава

- Источник состава — сайт **rs-red.com**, приватный эндпоинт `GET /api/subdivision/{id}` (для запроса нужна **cookie** сессии Steam).
- Cookie приходит в панель **автоматически** через браузерное расширение «RED ATK · Cookie Sync»: достаточно зайти на rs-red.com с установленным расширением. Запасной вариант — вставить cookie вручную: **Настройки → RS-RED → Cookie сайта rs-red.com** (F12 → Сеть → обновить страницу → первый запрос → заголовок `Cookie`).
- **Автосинхронизация** запускается планировщиком раз в 30 минут, но только если cookie задана. Пока состав пуст, на вкладке «Состав» будет подсказка: *«Состав пуст — нажмите "Синхронизировать с rs-red.com"»*.
- Как происходит слияние (логика `syncRoster`):
  1. боец из роster'а найден по `pid` → обновляются часы/звание/должность;
  2. не найден по `pid`, но совпал по имени → привязывается `pid`, обновляются данные;
  3. вообще не найден → создаётся новый боец;
  4. кто был в базе, но пропал из онлайна состава → получает метку **«выбыл»** (`active = false`), но не удаляется.

### 1.2. Как вручную синхронизировать состав

- Откройте вкладку **«Состав»** (панель слева) → нажмите кнопку **«Синхронизировать с rs-red.com»**.
- Либо на главной странице **«Обзор»** в блоке быстрых действий нажмите **«Синхронизация»**.
- Результат (успех/ошибка) сразу виден и дублируется в **«Журнал»**.

### 1.3. Ручное управление бойцами (вкладка «Состав»)

Права: **гость** видит состав только для чтения; **командир** и **администратор** могут редактировать. Админ должен быть авторизован (кнопка «Вход» в сайдбаре).

Что можно делать в таблице состава:

| Что сделать | Как |
|---|---|
| **Найти бойца** | поле поиска по имени над таблицей (Discord ID участвует в поиске только у штаба) |
| **Показать только должников** | фильтр «только должники» (кто не выполнил норму часов) |
| **Показать выбывших** | переключатель «показать выбывших» (строки с бейджем «выбыл») |
| **Привязать Discord ID** | в колонке «Discord ID» введите цифры в поле → нажмите **Enter** или кликните мимо поля — сохранится автоматически. Рядом появится зелёная иконка-ссылка. Пустое значение — ID будет убран. Колонка видна только командирам и администраторам. |
| **Назначить отпуск** | в колонке «Статус» щёлкните **тумблер** (янтарный). Строка подсветится, боец получит бейдж 🌴 «в отпуске». Повторное нажатие — снять отпуск. |
| **Смотреть норму** | часы отображаются цветом: зелёный — норма выполнена, жёлтый — на грани, красный — 0 ч / провал. По норме см. настройки (`norm_hours`, по умолчанию 10). |

**Что видят обычные бойцы:** табель без технических полей — Позывной, Звание и должность, Онлайн, Статус (в строю / в отпуске / выбыл). Discord ID и сводка «без Discord ID» — служебные данные штаба, личному составу они не показываются.

Важно: каждое изменение (Discord ID, отпуск) **автоматически пишется в «Журнал»** с указанием, кто и что изменил (код `PATCH /api/members/[id]`).

### 1.4. Отпуск через бота (альтернативный способ)

Помимо ручного тумблера, отпуск можно оформить заявкой в Discord:

1. Боец подаёт заявку в **канале отпуска** (ID — настройка `vacation_channel_id`) с текстом вида:
   ```
   Подразделение: Танковая рота
   Тип заявки: Отпуск
   Имя пользователя: Петров
   Даты отпуска: с 10.11.2026 по 20.11.2026
   ```
2. Вы (или модератор) нажимаете под заявкой реакцию **🟢 / :ATK:** → бот **выдаёт роль «Отпуск»** (ID роли — настройка `leave_role_id`), **синхронизирует статус в базе** (`vacation = true`, фиксируется дата окончания `vacationUntil`), **отправляет бойцу ЛС** с датой возвращения и создаёт ветку-итог. Реакция **❌** → отказ + ЛС.

### 1.5. Запросы ролей (выдача/снятие)

В разделе настроек «Бот заявок и Google Таблица» есть поле **«ID канала запросов ролей»** (по умолчанию `1090516508725215253`). В этом канале бот принимает команды на выдачу и снятие ролей.

**Формат сообщения** — 3 строки:

```text
@получатель
@экзаменатор
Выдать Капитан ТР, снять Друг АТК
```

Особенности:

- **Несколько ролей через запятую** — бот разберёт всё из одной строки: `Выдать Игроман, Игломан2, Снять Друг АТК`.
- **«Выдать …» и «Снять …» можно смешивать** в одной команде — действие действует начиная со своего слова до следующего `Выдать`/`Снять` (или до конца).
- **Составные звания** вида `Рядовой ТР`, `Капитан ТР`, `Ст. Лейтенант АД`, `Полковник АД` (суффикс — подразделение): бот **выдаёт комплект ролей** — подразделение (Танковая рота / Артиллерийский дивизион) + корпус + категорию «Звания» + роль самого звания, а также автоматически **снимает** у бойца «Новобранца» и «Друга АТК».
- **Снятие составного звания** — бот убирает роль звания и роль подразделения; если у бойца не осталось ни одного подразделения (ТР/АД), ему возвращается роль «Друг АТК».
- **Подтверждение реакцией**: экзаменатор (упомянутый во второй строке) или модератор нажимает **🟢 / :ATK:** → бот применяет роли и создаёт ветку-отчёт «Роли обновлены»; **❌** → отказ.
- Роли, содержащие слово `Модератор`/`Администратор`, выдать или снять **нельзя**.
- Каждый выполненный запрос фиксируется в **«Журнале»** панели (`kind: roles`).

## 2. Доступы к панели (вкладка «Доступы», только администратор)

### 2.1. Вход администраторов и командиров через Discord

Вкладка **«Доступы»** (`/users`) — управление аккаунтами панели. Кроме создания
аккаунта по логину и паролю здесь привязывается **Discord ID**:

| Что сделать | Как |
|---|---|
| **Привязать Discord вручную** | колонка «Discord ID» → впишите цифровой ID и нажмите иконку сохранения (зелёная «галочка-сохранение»). Пустое значение — привязка снимается. |
| **Связать существующего бойца** | селект «Связка с бойцом» → выберите бойца → сохраните. Его Discord ID перенесётся на аккаунт, а уровень доступа бойца поднимется до роли аккаунта (понижения не бывает). |
| **Сменить уровень прав** | селект «Уровень прав»: **Командир** (модерация, правки состава) или **Администратор** (полный доступ, включая эту вкладку). |

Как только Discord привязан, человек нажимает на странице входа **«Войти через
Discord»** — и сразу попадает в панель, без логина и пароля. Если он ещё и боец
в строю, рядом открывается личный кабинет: обе сессии живут одновременно.

**Что важно знать:**

- **Вход по логину и паролю сохраняется** как резервный способ — если Discord
  недоступен, доступ к панели не теряется.
- **Последнего администратора нельзя понизить или удалить** — панель осталась
  бы без управления аккаунтами навсегда.
- **Один Discord — один аккаунт**: если ID уже занят другим аккаунтом, панель
  откажет и назовёт занявший логин.
- **Роль из Discord не повышает прав**: доступ к панели даёт только совпадение
  Discord ID с записью в таблице аккаунтов и её роль `admin`/`officer`.
- **У бойца без Discord ID** связка выдаст роль, но вход через Discord
  заработает лишь после того, как ID появится в его карточке; панель об этом
  предупредит прямо в списке.

Все правки доступа пишутся в **«Журнал»** («Правка доступа»: кто, что и у кого
изменил).

## 3. Интеграция с Google Таблицами

### 3.1. Зачем она нужна

По ТЗ бот автоматически вносит правки в ШДС-таблицу подразделения при одобрении заявки из Discord. Поддерживаются **5 сценариев** (поле «Редакция ШДС» в заявке):

| Сценарий | Что делает бот в таблице |
|---|---|
| **Добавление в ШДС** | находит свободную строку «Вакант» в блоке добавления и вписывает звание, имя, Steam ID, Discord ID (формат Times New Roman, 12, по центру) |
| **Изменение звания** | находит строку бойца по имени и меняет звание |
| **Перенос и зачистка (должность)** | переносит бойца в блок нужной должности, а старую строку **зачищает шаблоном «Вакант»** |
| **Получение подтверждения об экзаменации** | закрашивает сданные экзамены в зелёный |
| **Убрать из таблицы** | сбрасывает строку бойца шаблоном «Вакант» |

Заявки на **отпуск** в таблицу не пишутся — они обрабатываются ролями и базой (см. п. 1.4).

### 3.2. Настройка сервисного аккаунта Google (пошагово)

Бот работает с таблицей **через сервисный аккаунт** — «паспорт» в виде JSON-файла.

1. Зайдите в **Google Cloud Console** → выберите (или создайте) проект.
2. Включите API: **APIs & Services → Enabled APIs** → нажмите **ENABLE APIS AND SERVICES** → включите **Google Sheets API** (обязательно) и **Google Drive API** (библиотека `google-spreadsheet` использует его для доступа к метаданным файла).
3. Создайте сервисный аккаунт: **Credentials → Create Credentials → Service Account** → дайте имя → роль **Editor** → **Done**.
4. У выбранного аккаунта нажмите **Manage keys → Add key → Create new key → JSON** → скачайте файл. Это и есть «паспорт», внутри него поля `"type": "service_account"`, `"client_email"`, `"private_key"` и т.д.
5. **Откройте вашу таблицу и поделитесь ею** с адресом `client_email` из скачанного JSON, выдав права **Editor** (кнопка «Поделиться» в правом верхнем углу таблицы).
6. Вставьте содержимое JSON в панель: **Настройки → «Бот заявок и Google Таблица» → «Паспорт сервисного аккаунта Google (JSON)`** → вставьте весь текст → внизу «Сохранить всё».

> Поле маскируется звёздочками (`••`); при сохранении замаскированное значение **не затирает** старое. Если поле оставить пустым — бот возьмёт паспорт из файла `src/lib/google-service-account.json` на сервере.

### 3.3. Подключение нужной таблицы

1. Скопируйте **ID таблицы** из ссылки:
   ```
   docs.google.com/spreadsheets/d/ВОТ_ЭТО_ID/edit
   ```
2. Вставьте его в настройки в поле **«ID Google-таблицы (ШДС)`** (`gsheet_spreadsheet_id`).
3. **Название листа должно точно совпадать с полем «Подразделение» из заявки** (без учёта регистра): например, лист «Танковая рота» или «Артиллерийский дивизион». Бот ищет лист по названию, а раскладку (колонку имени, блоки строк) — по словам из названия: «танк…» → раскладка роты, «дивизион/артиллер…» → раскладка дивизиона.
4. Таблица должна иметь **стандартную раскладку ШДС по ТЗ**: колонка имени с маркером «Вакант», блоки строк по должностям, строка заголовков экзаменов. Алгоритм ищет данные по фиксированным диапазонам строк (для роты: добавление — строки 42–56, командиры — 10–19, наводчики — 21–26, мехводы — 28–40, логисты/снабжение — 42–56; для дивизиона: добавление — 32–41, 1 ООВ — 12–20, 2 ООВ — 22–30, снабжение — 32–41). Если ваша таблица отличается — диапазоны корректируются в коде (`src/lib/gsheets.ts`, константы `LAYOUTS`).

### 3.4. Цикл заявки ШДС в Discord

1. Боец отправляет заявку в **канале заявок ШДС** (настройка `shds_channel_id`) в формате:
   ```
   Подразделение: Танковая рота
   Редакция ШДС: Добавление в ШДС
   Имя пользователя: Петров
   Звание: Рядовой
   Steam ID: STEAM_0:1:12345
   Discord ID: 123456789012345678
   Должность: Мехвод
   Сданные экзамены: Огневая, Тактика
   ```
2. Бот **не ставит реакции сам** — ждёт вашей ручной. Одобрить может **пользователь с ролью, упомянутой (пингованной) в заявке**, либо всегда **модератор** (настройка `moderator_role_id`).
3. **🟢 / :ATK:** → в таблицу вносится изменение → под заявкой создаётся ветка с итогом *(«ОДОБРЕНО И ВНЕСЕНО … Решил: …»)*. **❌** → «[ОТКАЗАНО]» + ЛС (для отпуска).
4. Каждая операция с таблицей пишется в **«Журнал»** (успех или ошибка с текстом — например, «Боец не найден», «Нет свободных строк "Вакант"»).

> Если таблица не настроена (нет ID или паспорта), одобренная ШДС-заявка вернёт ошибку `Не найден «паспорт» сервисного аккаунта…` / `Не задан ID Google-таблицы…` — это будет видно в журнале.

## 4. База знаний / Документация (вкладка «Документация»)

### 4.1. Режим просмотра

- Вкладка показывает **кнопки-ссылки** (название + URL) в заданном порядке.
- Сверху — **строка поиска** (ищет по названию) и **фильтр по тегам**: клик по чипу тега оставляет только документы с этим тегом (можно выбрать несколько).
- Документ может иметь до **4 тегов**.

### 4.2. Как редактировать (командир / админ)

1. Нажмите кнопку **«Редактировать»** — интерфейс перейдёт в режим редактирования (внизу появится липкая панель).
2. **Добавить ссылку**: кнопка добавления → заполните **«Название документа»** и **«Ссылка на документ»** (URL вида `https://…`).
3. **Назначить теги**: кнопка-чип **«+ тег»** → откроется окно выбора с галочками уже существующих тегов. Отметьте нужные (до 4) и закройте окно (Esc или клик мимо).
4. **Создать новый тег прямо из интерфейса**: в том же окне — блок **«Новый тег»** → введите название (до 40 символов) → **Enter** или кнопка **«Создать»**. Допустимо ввести сразу несколько. Тег появится в **общем списке**; чтобы привязать его к документу, отметьте его галочкой в списке выше.
5. **Снять тег** у документа: в строке документа кликните крестик **×** на чипе тега.
6. **Изменить порядок**: стрелки «вверх/вниз» у строки документа.
7. **Удалить документ**: кнопка «корзина» → подтверждение («удалить?»). Удаление тега из общего списка — аналогично, с подтверждением.
8. **Сохранить**: в липкой панели внизу нажмите **«Сохранить изменения»** (или **«Отмена»**, чтобы отбросить черновик).

Особенности:
- Пока не нажата «Сохранить изменения», правки видит только редактор (работа идёт с черновиком).
- При сохранении сервер **сам проверяет** URL (без `http`/`https` будет отброшено), чистит дубли тегов и лишние ссылки на удалённые теги.
- Каждое сохранение фиксируется в **«Журнале»**: сколько кнопок добавлено/удалено/изменено, сколько тегов создано/удалено.
- Права: редактировать могут **admin** и **officer**; гость — только просмотр.

## 5. Планировщик и автоматика

### 5.1. Как это устроено

- **Планировщик** стартует вместе с приложением (`src/lib/scheduler.ts`) и «тикает» каждые **20 секунд**.
- На каждом тике он проверяет текущее локальное время (часовой пояс — настройка `timezone`) и запускает задачу, если её время совпало с расписанием.
- **Защита от дублей**: запуск фиксируется в базе (`cron_runs`), поэтому даже если приложение перезапустили или сервер проспал минуту, один и тот же слот выполнится **только один раз**. Пропущенный слот не «догоняется», следующий сработает по расписанию.
- **Индикатор «Планировщик»** в сайдбаре: планировщик пишет heartbeat каждые ~20 сек; если он «остановлен» (красная точка), сообщение 90+ секунд не обновляется. Блок **«Система»** покажет статус: *Discord-бот / rs-red.com / Планировщик*.
- На **главной «Обзор»** показываются **ближайшие запуски** — что и когда будет выполнено.

### 5.2. Какие задачи выполняются автоматически

| Задача | Срабатывание | Что делает | Где настраивается |
|---|---|---|---|
| **1. Пинги на операцию** | Ежедневно в заданные времена (по умолчанию `14:45, 19:45`) | Отправляет в канал Discord случайный текст + гифку и **сам ставит реакции** ✅ ❌ ⏰ ❓ | «Настройки → Пинги на операцию»: тумблер **вкл**, поле «Время пингов» (ЧЧ:ММ через запятую) |
| **2. Недельная проверка онлайна** | В выбранные дни в заданное время (по умолчанию пт/сб/вс в `12:00`) | Собирает статистику (всего, 0 часов, норма, отпуск, должники), шлёт embed-отчёт в канал и **пингует должников** у кого указан Discord ID (у тех, кто в отпуске — не пингует) | «Настройки → Проверка онлайна»: тумблер **вкл**, «Дни проверки» (клики по Пн–Вс), «Время проверки» |
| **3. Автосинхронизация состава** | Раз в **30 минут**, если есть cookie | Обновляет состав с rs-red.com, чтобы панель была актуальной | Настроек не требует; отключается автоматически при отсутствии cookie |
| **4. Отпускные напоминания** | Связаны с датами `vacationUntil` | Логика уведомлений за 24 часа заложена в БД (поле `vacationNotified`) | — |

Важные поля настроек для задач 1–2: **ID канала Discord** (`discord_channel_id` — куда слать пинги и отчёты) и **ID роли для пинга на операцию** (`discord_role_id` — кого пинговать). Их можно скопировать в Discord так: ПКМ по каналу → «Копировать ID канала» (нужен режим разработчика), ПКМ по роли в настройках сервера → «Копировать ID роли».

### 5.3. Ручной запуск задач

На главной странице **«Обзор»** есть блок действий:
- **«Пинг на операцию»** — запустить задачу №1 сейчас (не отменяет расписание);
- **«Проверка онлайна»** — запустить задачу №2 сейчас;
- **«Синхронизация»** — синхронизировать состав сейчас.

После каждого запуска результат появляется в **«Журнале»** (kind `weekly` / `sync`).

## 6. Арсенал (вкладка «Арсенал», `/armory`)

Комплекты экипировки по специальностям: механик-водитель, наводчик-оператор, стрелок КМБТ и другие. Модуль отвечает за то, чтобы боец получил свою выкладку **без переписки в личке**.

### 6.1. Кто что видит

| Действие | Кто |
|---|---|
| Смотреть каталог и копировать строки | Любой вошедший: боец из кабинета или сотрудник панели |
| Видеть архивные (снятые) комплекты | Командир и администратор (кнопка «Показать архив») |
| Создавать, править, убирать в архив | Командир и администратор |

Гостю раздел недоступен: он видит каталог только после входа. Проверка выполняется и в интерфейсе (кнопки), и на сервере (`/api/armory`, `/api/admin/armory`) — скрытой кнопки мало, роут отвечает сам.

### 6.2. Как завести комплект

1. Зайдите в **ACE Arsenal** в игре, соберите выкладку, нажмите **Ctrl+C** — строка скопирована в буфер.
2. В панели: **Арсенал → Новый комплект**.
3. Заполните название, подразделение, код специальности (необязательно) и тактическое пояснение.
4. Вставьте строку в поле **«Строка ACE Arsenal»** — она сохраняется **дословно**, пересобирать её руками не нужно.
5. Заполните слоты выкладки (форма, разгрузка, шлем, рюкзак, оружие, медицина, БК, спецсредства) — по ним рисуется карточка и собирается **текстовый табель**.
6. Кнопка **«Собрать заготовку SQF»** положит в поле SQF корректный по синтаксису каркас; замените в нём класснеймы настоящими или вставьте готовый массив из Eden.
7. **Сохранить**. Комплект сразу появится у состава.

Поля «форма», «разгрузка» и «шлем» обязательны: комплект без СИБЗ — это ошибка шаблона, и панель его не сохранит. Остальные слоты можно оставить пустыми — в карточке и табеле будет честное «не выдаётся».

### 6.3. Что копирует боец

В панели комплекта три кнопки — каждая под свой сценарий:

| Кнопка | Что в буфере | Куда вставлять |
|---|---|---|
| **📋 Скопировать для ACE Arsenal** | Строка экспорта | В окне ACE Arsenal — **Ctrl+V** |
| **💻 Скопировать SQF (Eden)** | `player setUnitLoadout […];` | Eden Editor (инициализация бойца, триггер) |
| **📄 Текстовый табель** | Читаемый чек-лист с количествами | В чат, в печать, в рапорт |

Зелёная галочка на кнопке означает, что строка в буфере. Если браузер запретил доступ к буферу обмена (панель открыта по `http` во внутренней сети), появится подсказка — строку можно выделить в развёрнутом блоке ниже и скопировать вручную.

### 6.4. Архив вместо удаления

Удаления комплектов нет: кнопка **«В архив»** снимает выкладку с выдачи, но оставляет её в базе — по ней уже выдавали экипировку, и при разборе нужно видеть, что именно. Вернуть комплект можно той же кнопкой (**«Вернуть из архива»**).

Все правки комплектов пишутся в **«Журнал»** (раздел «Арсенал»): видно, кто, когда и какой комплект менял.

## 7. Чек-лист первого запуска (для администратора)

1. **Настройки → Discord**: токен бота, ID канала, ID роли для пинга.
2. **Расширение Cookie Sync**: установите, откройте rs-red.com — cookie уйдёт сама (проверьте блок «RS-RED» и дату «Последняя cookie»).
3. **Состав**: вкладка «Состав» → «Синхронизировать с rs-red.com» → проставьте бойцам **Discord ID** и **отпуска**.
4. **Доступы командиров**: вкладка «Доступы» → привяжите свой Discord ID и Discord ID командирам (или свяжите их с бойцами из состава) — дальше они входят кнопкой «Войти через Discord».
5. **Google Таблицы**: создайте сервисный аккаунт, включите Sheets/Drive API, добавьте `client_email` в таблицу, вставьте JSON и ID таблицы в **Настройки → «Бот заявок и Google Таблица»**; пропишите ID каналов ШДС/отпуска и роли модератора/«Отпуск».
6. **Документация**: добавьте первые ссылки и теги на вкладке «Документация».
7. **Расписание**: проверьте «Пинги на операцию», «Проверку онлайна», норму часов и часовой пояс; на главной «Обзор» убедитесь, что индикатор **«Планировщик: работает»**.
8. Итоговый контроль — вкладка **«Журнал»**: все события (синхронизация, пинги, заявки, изменения состава/документации/настроек) фиксируются там.

**Небольшие примечания к коду (для разработчика):**
- Диапазоны строк и соответствие «колонка имени / Steam / Discord / экзамены» зашиты в `LAYOUTS` в `src/lib/gsheets.ts` — если ваша таблица не совпадает со стандартом ТЗ, правятся именно эти константы.
- Авторизация правок состава/документов идёт через JWT-сессию (`officer`/`admin`); вкладка «Настройки» доступна только `admin`.
- При перезапуске сервера планировщик стартует автоматически (`src/instrumentation.ts`), дубли исключены благодаря таблице `cron_runs`.
