# Развёртывание RED OPS на VPS

Полный гид по переносу панели и бота на собственный сервер с круглосуточной
автономной работой.

---

## Что вы разворачиваете

Один сервер держит всё сразу:

```
┌──────────────────────────── VPS ────────────────────────────┐
│                                                             │
│  ┌─────────┐   Дневной/автоматический режим 24/7            │
│  │ RED OPS │ ─ планировщик: пинги в Discord по расписанию   │
│  │ (Next)  │ ─ проверка онлайна пт/сб/вс                    │
│  │ :3000   │ ─ приём cookie от вашего расширения            │
│  └────┬────┘ ─ веб-панель: http(s)://ваш-домен              │
│       │                                                     │
│  ┌────▼─────┐                                               │
│  │PostgreSQL│ ─ состав, отпуска, настройки, логи, снимки    │
│  └──────────┘                                               │
└─────────────────────────────────────────────────────────────┘
        ▲                                      ▲
        │ cookie                               │ запросы
┌───────┴────────┐                     ┌───────┴────────┐
│ Расширение в   │                     │    Discord     │
│ вашем браузере │                     │ (сервер + бот) │
└────────────────┘                     └────────────────┘
```

Важно: панель — это **настоящий сайт**, а не локальная страничка. После
развёртывания она живёт по постоянному адресу вида `https://panel.ваш-домен.ru`
(или `http://IP:3000` без домена), доступна 24/7 из любого браузера. Бот не
зависит от вашего компьютера: пинги и проверки онлайна выполняет сам VPS.
От компьютера нужно только расширение, которое держит cookie rs-red.com свежей.

---

## Требования

- VPS: 1 vCPU / 1–2 ГБ RAM / 10 ГБ диск (Ubuntu 22.04 или 24.04).
- Доступ по SSH со своего компьютера.

---

## 1. Установка Docker на VPS

```bash
ssh user@IP-ВАШЕГО-СЕРВЕРА

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
exit
# зайдите снова
ssh user@IP-ВАШЕГО-СЕРВЕРА
docker compose version   # должен быть плагин v2
```

## 2. Загрузка проекта на сервер

Вариант А — если проект в git-репозитории:

```bash
git clone <ваш-репозиторий> redops
cd redops
```

Вариант Б — копия с компьютера (выполнять на КОМПЬЮТЕРЕ, не на сервере):

```bash
scp -r ./папка-проекта user@IP-ВАШЕГО-СЕРВЕРА:~/redops
```

Никаких node_modules и .next копировать руками не нужно — Docker соберёт всё сам.

## 3. Файл .env

```bash
cd ~/redops
cp .env.example .env
nano .env
```

Обязательно смените `POSTGRES_PASSWORD` на длинный случайный.
`DISCORD_BOT_TOKEN` можно не заполнять — токен удобнее ввести в самой панели.
Сохраните файл.

## 4. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает 3–6 минут. Порядок старта автоматический:
поднимается PostgreSQL → сервис `migrate` применяет схему БД → стартует панель.

Если ваша версия compose не понимает `condition: service_completed_successfully`:

```bash
docker compose up -d db
docker compose run --rm migrate
docker compose up -d --build app
```

## 5. Проверка

```bash
docker compose ps                    # три сервиса: db, migrate (exited 0), app
docker compose logs -f app           # Ctrl+C чтобы выйти
curl http://localhost:3000/api/health
# {"ok":true}
```

Откройте в браузере: `http://IP-ВАШЕГО-СЕРВЕРА:3000` — должна загрузиться панель.

## 6. Домен и HTTPS (настоятельно рекомендуется)

Cookie rs-red.com — это сессия, поэтому ходить по открытому HTTP нельзя.
С доменом HTTPS получается автоматически через Caddy.

**6.1. DNS.** У регистратора домена создайте A-запись:
`panel.вашдомен.ru → IP VPS`. Подождите его пропагации (обычно минуты).

**6.2. Установка Caddy:**

```bash
sudo apt update
sudo apt install -y caddy
```

**6.3. Конфиг `/etc/caddy/Caddyfile`:**

```
panel.вашдомен.ru {
    reverse_proxy 127.0.0.1:3000
}
```

**6.4. Применяем:**

```bash
sudo systemctl reload caddy
```

Через ~30 секунд сертификат выпущен, панель доступна как
`https://panel.вашдомен.ru`. Caddy сам продлевает сертификат.

**6.5. Закройте прямой доступ на порт 3000** — в `docker-compose.yml` замените
маппинг портов на локальный и перезапустите:

```yaml
    ports:
      - "127.0.0.1:3000:3000"
```

```bash
docker compose up -d app
```

## 8. Финальная настройка бота (один раз, из панели)

Откройте `https://panel.вашдомен.ru/settings`:

1. **Discord**: токен бота, ID канала, ID роли.
2. **Автосинхронизация cookie**: скачайте расширение — архив автоматически
   соберётся с адресом `https://panel.вашдомен.ru` и действующим ключом.
   Это постоянный URL, поэтому расширение устанавливается **один раз навсегда**:
   распаковать → `chrome://extensions` → загрузить распакованное.
3. **RS-RED**: ID подразделения (5).
4. Вернитесь в **Состав** → «Синхронизировать с rs-red.com» — как только
   расширение пришлёт cookie, подтянется состав. Проставьте бойцам Discord ID
   и отпуска.
5. Готово. Дальше VPS работает сам: пинги в 14:45 и 19:45 ежедневно,
   проверка онлайна и статистика — пн… то есть пт/сб/вс в 12:00.
   Вы только управляете отпусками.

## 9. Дополнительная защита панели (опционально)

У панели нет логина — держите её адрес при себе. Хотите пароль на интерфейс —
Caddy умеет basicauth (API расширения при этом останется под защитой
ключа синхронизации):

```
panel.вашдомен.ru {
    handle /api/* {
        reverse_proxy 127.0.0.1:3000
    }
    handle {
        basicauth /* {
            admin ХЕШ_ПАРОЛЯ
        }
        reverse_proxy 127.0.0.1:3000
    }
}
```

Хеш пароля:

```bash
docker run --rm caddy caddy hash-password --plaintext 'ВАШ-ПАРОЛЬ'
```

## 10. Обслуживание

Логи:

```bash
docker compose logs -f app
docker compose logs -f db
```

Перезапуск:

```bash
docker compose restart app
```

Обновление кода (на сервере в папке проекта):

```bash
git pull                     # или снова scp файлов
docker compose up -d --build
```

Бэкап базы (состав, отпуска, настройки, логи, снимки):

```bash
docker compose exec db pg_dump -U postgres app_db > backup-$(date +%F).sql
```

Восстановление:

```bash
cat backup-2026-08-24.sql | docker compose exec -T db psql -U postgres app_db
```

Автобэкап каждые сутки (crontab на сервере):

```
0 5 * * * cd /home/user/redops && docker compose exec -T db pg_dump -U postgres app_db | gzip > /home/user/backups/redops-$(date +\%F).sql.gz
```

## 11. Решение проблем

| Симптом | Что сделать |
|---|---|
| `migrate` падает с ошибкой соединения | Проверьте `POSTGRES_PASSWORD` в .env — одинаковый во всех сервисах через подстановку compose. Повторите `docker compose up -d`. |
| Панель 502/недоступна через домен | DNS ещё не пропагировался, либо `app` слушает только 127.0.0.1, а Caddy на другом хосте. Смотрите `docker compose logs app`, `systemctl status caddy`. |
| Дискорд не пингует | Настройки → Discord: токен/канал/роль. Статус в сайдбаре и Журнал покажут текст ошибки Discord API. |
| «Сайт отклонил доступ (403)» в журнале | Cookie устарела — просто откройте rs-red.com в браузере с расширением: свежая уйдёт автоматически. |
| Сервер перезагрузился | `restart: always` поднимет стек сам. Cron-слот, попавший на минуты простоя, пропустится (защита от дублей), следующий сработает нормально. |
